## Почему Фаза 5 отменена

Разбиение workspace на крейты обосновывалось как «единственное лекарство от
стоимости сборки». Замер это не подтвердил:

- тёплый цикл «правка → работающий backend» — **14 с**, из них ~9 с тайп-чек и
  ~5 с кодогенерация с линковкой. Разбиение било бы по большей половине
  (9 → ~3 с), то есть дало бы 14 → ~8 с. Шесть секунд за перестройку 43 срезов —
  плохой размен;
- самое дорогое место в проекте — фронт (≈30 с), и **11 с из них** это
  `wasm-bindgen`, который работает над уже слинкованным `.wasm`. Крейты его не
  ускоряют вообще;
- дорого не «собирать», а **терять инкрементальность** (14 → 114 с), и это тоже
  не лечится границами крейтов.

**Что из фазы стоит сохранить, но по другим основаниям:** вынос `shared/llm`
(22 204 строки) — ради *границы*, а не скорости; он тянет `async-openai`,
`rquickjs`, `ammonia` и является крупнейшим безымянным блоком проекта (Цель 4
программы). Аналогично `plugins` и `mail`.

## Грабли, выясненные дорогой ценой

Не переоткрывать.

1. **Три независимых набора артефактов.** `cargo check` пишет
   `libbackend-*.rmeta`, `cargo test` — `deps/backend-<hash>.exe` (104 МБ),
   `cargo run`/`build --bin` — `debug/backend.exe` (103 МБ). Прогон одной
   команды **не греет** две другие. CLAUDE.md говорил про «два профиля» — их три.
2. **Замерять надо `build --bin`, а не `check`.** `check` не делает
   кодогенерацию и не линкует 103 МБ; вывод по нему о стоимости разработки
   будет заниженным в разы.
3. **`cargo clean -p backend` сносит артефакты по всем таргетам** (десятки ГиБ).
   После него любая сборка холодная — не путать с «проект медленный».
4. **Генерируемые `*_gen.rs` нельзя форматировать.** `contracts/build.rs`
   пишет 61 `metadata_gen.rs` + `registry_gen.rs` прямо в `src/`;
   `write_if_changed` вернёт неформатированный вид на следующей сборке.
   CI фильтрует их из отчёта `cargo fmt`.
5. **`git ls-files | xargs rustfmt` ≠ `cargo fmt`.** Второй ходит по дереву
   `mod`, первый видит и файлы вне его (их 6). Гейт должен фильтровать вывод
   `cargo fmt`, а не собирать список файлов сам.
6. **Пустые каталоги git не отслеживает.** «Убрать призраков» из Цели 7 —
   гигиена рабочей копии, в репозиторий не попадает. Настоящие призраки —
   6 файлов вне дерева модулей.
7. **PowerShell 5.1: `.ps1` с не-ASCII нужен BOM**, иначе он читается как ANSI и
   ломается парсинг. И **никакого `2>&1` на нативных командах** — под
   `$ErrorActionPreference='Stop'` это роняет скрипт на выводе cargo в stderr.
8. **`NO_COLOR=1` ломает `trunk`** (ждёт `true`/`false`).
9. **Проба в измерителе меняет mtime.** Cargo фингерпринтит path-зависимости по
   mtime, поэтому восстанавливать надо и содержимое, и метку времени — иначе
   следующая сборка зря пересобирается. Исправлено в `measure_build.ps1`.

**Как работает храповик.** Гейтится метрика, у которой в
`system/metrics/catalog.rs` есть *и* направление, *и* пороги (`with_limits`).
Список не дублируется в скрипте — выводится из каталога. Допуск — собственная
точность метрики (`precision`): изменение, невидимое на странице метрик, не
блокирует. Осознанный размен — `SKIP_HEALTH=1 git commit …`.

**Как добавить метрику:** счётчик в `tools/gen_code_metrics.ps1` + запись в
`catalog.rs`. Без второго тест `every_embedded_key_is_described_in_catalog`
завалит сборку — это сделано намеренно.

## Фаза 3. `AppState` + `ApiError` — ✅ выполнено 2026-08-17

Водораздел пройден: проект перестал быть структурно нетестируемым.

### Что сделано

**Крейт разделён на библиотеку и бинарь.** Оказалось, что препятствий было не
одно, а два: `crates/backend` был **чисто бинарным**, а интеграционные тесты
компилируются отдельным крейтом и линкуются против библиотеки — которой не
существовало. Вся модульная структура уехала в `src/lib.rs`, `main.rs` остался
стартовой процедурой. Побочный эффект: **впервые запускаются доктесты** (у
бинарного крейта их не бывает) — один битый пример нашёлся сразу.

**3a. `AppState`.** `shared/app_state.rs`: `AppState { db }`, прокинут через
`Router::with_state`; все 82 функции-конструктора роутеров теперь возвращают
`Router<AppState>`. `FromRef<AppState> for DatabaseConnection` позволяет
хендлеру просить `State<DatabaseConnection>`, не зная про остальные поля.

`get_connection()` **оставлен рабочим мостом** — 182 файла ходят через него, и
переводить их одним коммитом непроверяемо. Мост измеряется новой метрикой
`api.global_db_files` (182): пока она не ноль, второй экземпляр приложения в
процессе невозможен.

**Эталонный срез — a002_organization**, переведён на всю глубину: хендлер берёт
`State`, `service` и `repository` принимают `&DatabaseConnection` параметром.
28 внешних вызовов a002 получили явный `db::get_connection()` аргументом —
поэтому счётчик файлов с мостом временно **вырос** (166 → 182): обращение к
глобалу переехало из недр репозитория в место вызова, где его видно. Это
промежуточное состояние миграции, а не регресс.

**3b. `ApiError`.** `shared/error.rs`: перечисление на `thiserror` +
`IntoResponse` с телом RFC 9457 (`application/problem+json`). Текст `DbErr`
логируется, но наружу не уходит (в сообщениях SQLite — имена таблиц и куски
запроса); на это есть тест. `From<StatusCode>` — мост, благодаря которому
привычные `.map_err(|_| StatusCode::…)?` продолжают работать; **418 сигнатур
переведено** (377 однострочных + 43 многострочных, часть пересеклась),
`api.status_only_errors` = 0. Регекс метрики заодно починен: раньше он не видел
многострочную форму с висящей запятой, и такие сигнатуры проходили мимо гейта.

**Фронт.** `api_utils` получил типизированный `ApiError` (`Network` / `Status
{ status, code, detail }` / `Decode`) с разбором problem+json и предикатами
`is_unauthorized/is_forbidden/is_not_found`. Старые `get_json`/`post_json`
сохранены и отдают `String` через `Display`, поэтому ни один из 157 вызывающих
файлов не тронут; типизированный путь — `try_get_json`/`try_post_json`.
Контракт «различать 401 по подстроке» из документации убран.

**5 интеграционных тестов** — `crates/backend/tests/a002_organization_api.rs`:
round-trip POST→GET→список, problem+json на 404, 400 на кривой id, 401 без
токена (слой `check_scope` на месте, токен настоящий), прогон миграций.

### Найдено по дороге: установка с нуля была сломана

Первый же тест на пустой базе показал, что **цепочка миграций не проходит от
нуля**. `0001_baseline_schema.sql` подписан «used for fresh installations», но
дальше цепочка обращается к таблицам и колонкам, которых ни одна миграция не
создаёт: их правили руками в боевой базе до введения миграций. Падало на `0026`
(`ALTER TABLE general_ledger_entries RENAME TO sys_general_ledger` — такой
таблицы нет), затем ещё в трёх местах (p909/p910 `entry_date` и
`general_ledger_ref`, переименование p911 в `p911_wb_advert_by_items`, `srid` у
p903). Никто не замечал: боевая база существует непрерывно, нового инстанса с
нуля никто не поднимал.

Починено в `migration_runner`: на **полностью пустой** базе цепочка идёт
ступенями, между ступенями встают четыре заплатки (`PRE_BASELINE_PATCHES`).
Правкой самих миграций это сделать нельзя — изменится контрольная сумма давно
применённой миграции, и sqlx откажется работать с боевой базой; новой миграцией
тоже нельзя — она встанет в конец, а дыры в середине. Результат сверен с боевой
схемой: **108 таблиц против 108**, расхождение — 4 колонки, добавленные мимо
миграций уже после, и мёртвая `sys_journal_entries`.

### Грабли Фазы 3 (не переоткрывать)

10. **`sqlite::memory:` не годится для тестовой базы.** In-memory база
    принадлежит *соединению*: пул открывает второе — и оно попадает в пустую
    базу. Симптомы разные и обманчивые: то «no such table: _sqlx_migrations», то
    401 (секрет JWT читался из другой базы). `cache=shared` чинит владение, но
    приносит `SQLITE_LOCKED`, который не лечится `busy_timeout`. Тестовая база —
    **файл в TEMP с pid в имени**.
11. **Секрет JWT нельзя оставлять на ленивую генерацию в тестах.**
    `get_jwt_secret()` при пустой таблице генерирует новый и сохраняет; два
    параллельных теста успевают сгенерировать по своему, и токен, подписанный
    первым, проверяется вторым → 401. Секрет ставится один раз в
    `init_test_database`, до выдачи роутера.
12. **`init_test_database` нужен замок.** Тесты в бинаре идут параллельно; без
    `Mutex` второй вызов начинает поднимать свою базу и проигрывает гонку на
    `OnceCell::set`, а первый уже отдал роутер против немигрированной базы.
13. **Массовая правка сигнатур безопасна, потому что её проверяет компилятор.**
    Скриптом переведены сигнатуры и `Err(StatusCode::…)`; всё остальное
    (`?`-конверсии) работает само через `From<StatusCode>`. Из ~420 замен
    компилятор поймал 7 перегибов — там, где функция действительно возвращает
    голый статус (`insert_test_data`) или кортеж `(StatusCode, Json)`.

Крупные группы без политики: `/api/a018-llm-chat/*` (jobs, workspace,
attachments), `/api/ext/v1/*` (внешний API — **10 маршрутов, потребители 1С и
Power BI**), `/api/a012/wb-sales/*`, `/api/a034/ym-realization/*`,
`/api/general-ledger/*`, `/api/sys/tasks/*`.

Обе цифры закреплены константами-храповиками в
`system/access/route_registry.rs` (`ROUTES_WITHOUT_POLICY_BASELINE = 221`,
`ORPHAN_POLICY_BASELINE = 0`): новый маршрут без политики валит сборку сразу,
новый фантом — тоже. **Уменьшили долг — уменьшите константу**, тест требует
этого явно, иначе планка тихо перестанет держать достигнутое.

> Оптом 250 записей проставить нельзя: каждая — решение о `scope_id` и
> `PolicyMode`, а неверная запись о политике хуже отсутствующей, потому что
> выглядит проверенной.

cargo check -p contracts
