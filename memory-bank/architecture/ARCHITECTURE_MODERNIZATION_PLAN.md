## Почему Фаза 5 отменена

Разбиение workspace на крейты обосновывалось как «единственное лекарство от
стоимости сборки». Замер это не подтвердил:

- тёплый цикл «правка → работающий backend» — **14 с**, из них ~9 с тайп-чек и
  ~5 с кодогенерация с линковкой. Разбиение било бы по большей половине
  (9 → ~3 с), то есть дало бы 14 → ~8 с. Шесть секунд за перестройку 43 срезов —
  плохой размен;
- самое дорогое место в проекте — фронт (≈30 с), и **11 с из них** это
  `wasm-bindgen`, который работает над уже слинкованным `.wasm`. Крейты его не
  ускоряют вообще;
- дорого не «собирать», а **терять инкрементальность** (14 → 114 с), и это тоже
  не лечится границами крейтов.

**Что из фазы стоит сохранить, но по другим основаниям:** вынос `shared/llm`
(22 204 строки) — ради *границы*, а не скорости; он тянет `async-openai`,
`rquickjs`, `ammonia` и является крупнейшим безымянным блоком проекта (Цель 4
программы). Аналогично `plugins` и `mail`.

## Грабли, выясненные дорогой ценой

Не переоткрывать.

1. **Три независимых набора артефактов.** `cargo check` пишет
   `libbackend-*.rmeta`, `cargo test` — `deps/backend-<hash>.exe` (104 МБ),
   `cargo run`/`build --bin` — `debug/backend.exe` (103 МБ). Прогон одной
   команды **не греет** две другие. CLAUDE.md говорил про «два профиля» — их три.
2. **Замерять надо `build --bin`, а не `check`.** `check` не делает
   кодогенерацию и не линкует 103 МБ; вывод по нему о стоимости разработки
   будет заниженным в разы.
3. **`cargo clean -p backend` сносит артефакты по всем таргетам** (десятки ГиБ).
   После него любая сборка холодная — не путать с «проект медленный».
4. **Генерируемые `*_gen.rs` нельзя форматировать.** `contracts/build.rs`
   пишет 61 `metadata_gen.rs` + `registry_gen.rs` прямо в `src/`;
   `write_if_changed` вернёт неформатированный вид на следующей сборке.
   CI фильтрует их из отчёта `cargo fmt`.
5. **`git ls-files | xargs rustfmt` ≠ `cargo fmt`.** Второй ходит по дереву
   `mod`, первый видит и файлы вне его (их 6). Гейт должен фильтровать вывод
   `cargo fmt`, а не собирать список файлов сам.
6. **Пустые каталоги git не отслеживает.** «Убрать призраков» из Цели 7 —
   гигиена рабочей копии, в репозиторий не попадает. Настоящие призраки —
   6 файлов вне дерева модулей.
7. **PowerShell 5.1: `.ps1` с не-ASCII нужен BOM**, иначе он читается как ANSI и
   ломается парсинг. И **никакого `2>&1` на нативных командах** — под
   `$ErrorActionPreference='Stop'` это роняет скрипт на выводе cargo в stderr.
8. **`NO_COLOR=1` ломает `trunk`** (ждёт `true`/`false`).
9. **Проба в измерителе меняет mtime.** Cargo фингерпринтит path-зависимости по
   mtime, поэтому восстанавливать надо и содержимое, и метку времени — иначе
   следующая сборка зря пересобирается. Исправлено в `measure_build.ps1`.

## Инструменты, заведённые Фазами 0–1

| Файл | Назначение |
|---|---|
| `architecture.toml` | Машиночитаемый стандарт: слои, диапазоны, роли числами замера, hub-исключения, `[deviations]` |
| `tools/measure_build.ps1` | 8 замеров стоимости сборки → `build_timings.json`. 10–20 мин, в хук не входит |
| `tools/check_health.ps1` | **Храповик.** Сравнивает метрики с `HEAD`, валит коммит на регрессии |
| `.github/workflows/ci.yml` | fmt, `check` ×3, тесты backend, clippy (advisory), храповик против базовой ветки |

**Как работает храповик.** Гейтится метрика, у которой в
`system/metrics/catalog.rs` есть *и* направление, *и* пороги (`with_limits`).
Список не дублируется в скрипте — выводится из каталога. Допуск — собственная
точность метрики (`precision`): изменение, невидимое на странице метрик, не
блокирует. Осознанный размен — `SKIP_HEALTH=1 git commit …`.

**Как добавить метрику:** счётчик в `tools/gen_code_metrics.ps1` + запись в
`catalog.rs`. Без второго тест `every_embedded_key_is_described_in_catalog`
завалит сборку — это сделано намеренно.

## Фаза 3. `AppState` + `ApiError` — водораздел

Самая содержательная из оставшихся. До неё проект не поддаётся интеграционному
тестированию **структурно**, а не по недосмотру.

### 3a. `AppState` вместо глобального синглтона

**Проблема, замеренная:** `static DB_CONN: OnceCell` в
`shared/data/db.rs:10`; `get_connection()` вызывается в **166 файлах**;
`with_state`/`State<>` в backend — **0 вхождений**; `initialize_database()`
зовётся только из `main.rs:70`. Следствие: 573 из 611 тестов — синхронные
`#[test]` по чистым функциям, `#[tokio::test]` всего 38, интеграционных **0**.

**Порядок работ:**
1. `AppState { db: DatabaseConnection, … }`, прокинуть через `Router::with_state`.
2. **`get_connection()` сохранить** как deprecated-мост к `OnceCell` — иначе
   миграция превращается в один коммит на 166 файлов.
3. Мигрировать срез за срезом: `api/handlers/*` → `domain/*/repository.rs` →
   `service.rs`. Проверка после каждого — `cargo check -p backend`.
4. Как только `AppState` есть — интеграционный тест на `sqlite::memory:`
   с прогоном миграций и `tower::ServiceExt::oneshot`.
   **`tower` уже в dev-dependencies** ровно для этого (`crates/backend/Cargo.toml`).
5. Тесты класть в `crates/backend/tests/` — метрика `tests.integration`
   считает именно там.

### 3b. Типизированный `ApiError`

- `enum ApiError` на `thiserror` (**уже в зависимостях**, использован 1 раз) +
  `impl IntoResponse`, тело по RFC 9457 (`type`/`title`/`status`/`detail`/`code`).
- Заменить `Result<_, StatusCode>` (377 штук) на `Result<_, ApiError>`.
- Фронт: `api_utils` отдаёт типизированную ошибку вместо `String`; уходит
  матчинг по подстроке `"HTTP error: 404"` (`api_utils.rs:113`, прямо
  задокументирован в комментарии на строке 99).

**Метрики фазы:** `api.status_only_errors` 377 → 0, `tests.integration` 0 → >0.

## Долг доступа (найден в Фазе 1, в фазы не входил)

**250 маршрутов из 523 без записи в `ROUTE_REGISTRY`; 31 запись указывает на
несуществующий маршрут.** Заголовок модуля обещал «every endpoint must have
exactly one entry» и «tests will catch gaps» — **оба утверждения были ложны**.

Реестр читает только `system/audit/` — это **аудит, не enforcement** (защита в
middleware `check_scope`), поэтому дыры в доступе нет. Но страница аудита
отчитывается по 304 маршрутам, из которых 31 не существует, и не видит 250.

**31 фантом — следы переименования путей** на префиксы `aNNN`
(`/api/wb_sales/:id` → `/api/a012/wb-sales/:id`). Чинится **переуказанием
пути**, а не удалением: каждая правка убирает фантом и одновременно уменьшает
долг в 250. Это хороший первый заход — работа парная и проверяемая тестом.

Обе цифры закреплены константами-храповиками в
`system/access/route_registry.rs` (`ROUTES_WITHOUT_POLICY_BASELINE`,
`ORPHAN_POLICY_BASELINE`): новый маршрут без политики валит сборку сразу.
**Уменьшили долг — уменьшите константу**, тест этого требует.

> Оптом 250 записей проставить нельзя: каждая — решение о `scope_id` и
> `PolicyMode`, а неверная запись о политике хуже отсутствующей, потому что
> выглядит проверенной.
