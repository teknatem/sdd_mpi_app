# UI Standard

Нормативный документ фронтенда: **что разрешено**. Фактическая половина —
`UI_REGISTRY.md` в корне (генерируется из CSS+Rust): **что есть на самом деле**.

> Смотри `UI_REGISTRY.md` **до** того, как заводить новый класс. В проекте 589
> блок-рутов на ~15 реальных концепций — почти наверняка нужный блок уже есть
> под другим именем.

Каждое правило имеет ID. Пометка показывает, кто его проверяет:

- **[авто]** — `tools/gen_ui_registry.ps1` (детерминированно, в pre-commit hook);
- **[скилл]** — `/ui-check` по диффу (требует суждения);
- **[глаз]** — только ревью.

Правило без ID — не правило, а пожелание. Если проверить нельзя, так и написано.

## 1. Структура страницы

| ID | Правило | |
|----|---------|--|
| **UI-001** | Корень страницы — `<PageFrame page_id="{entity}--{category}" category=PAGE_CAT_*>`. Руками `<div class="page" id=...>` не писать. | [авто] |
| **UI-002** | `page__header` и `page__content` — **прямые** дети корня страницы. | [авто] |
| **UI-003** | Вкладки **уровня страницы** — `div.page__tabs` + нативные `button.page__tab`, **между** header и `page__content` (не внутри). Не Thaw `<Button>`. | [скилл] |
| **UI-003б** | `TabsVariant::Heavy` — просьба, а не гарантия: `PageTabs` сам вырождает «черепицу» в подчёркивания, когда не хватает ширины **или** активна весёлая тема (`kind=fancy`), где тяжёлая графика спорит с фоновой картинкой. Страница вариант не выбирает по теме — за неё это делает компонент. | [глаз] |
| **UI-003a** | Вкладки **внутри контента** (не уровня страницы) — `div.detail-tabs` + `button.detail-tabs__item` / `--active`. Это единственный underline-вариант; свой набор правил под подчёркивание не заводить. Геометрия выверена по `sys_tasks`. | [скилл] |
| **UI-004** | Категория из `shared/page_standard.rs`. `legacy` — честная пометка «ещё не по стандарту», а не способ обойти проверку; `custom` — осознанно свободная вёрстка. | [авто] |

Детали и шаблоны: `detail-page-standard.md`, `css-page-structure.md`.

## 2. Имена классов и реестр

| ID | Правило | |
|----|---------|--|
| **UI-010** | Новый блок-рут внесён в `crates/frontend/static/ui-registry.allow.json` с `reason`. Одобрение = строка в allowlist. | [авто] |
| **UI-011** | Блок определён **ровно в одном файле**. Блок, размазанный по нескольким файлам, не имеет владельца. | [авто] |
| **UI-012** | BEM: `block__element--modifier`, максимум 2 уровня вложенности. Модификатор всегда вместе с базовым классом. | [скилл] |
| **UI-013** | Запрещены `.checkbox-cell`, `.tableCell`, голый `.cell`, и вообще неспецифичные глобальные имена (`.active`, `.status`, `.value`, `.name`). | [авто] |
| **UI-014** | Per-page CSS живёт в `static/pages/<page>.css` и **весь** скоупится под корневым классом страницы. Переопределять глобальный блок (`.modal`, `.page__content`, `.table`) из page-файла нельзя. | [скилл] |

## 3. Токены

| ID | Правило | |
|----|---------|--|
| **UI-020** | Цвета — только через токены. Хардкод `#rrggbb` / `rgba()` вне `static/themes/*/` запрещён. | [авто] |
| **UI-021** | Отступы, размеры шрифта, радиусы, z-index — через `var(--spacing-*)`, `var(--font-size-*)`, `var(--radius-*)`, `var(--z-*)`. Сырой px допустим только там, где подходящего токена нет. | [авто] |
| **UI-022** | `var(--x)` без определения — **баг, а не стиль**: значение невалидно и свойство просто не применяется. Раздел «Used but never defined» в `UI_REGISTRY.md` должен быть пуст. | [авто] |
| **UI-023** | Все темы (`dark` / `light` / `forest`) определяют один и тот же набор токенов. Раздел «Theme drift» должен быть пуст. | [авто] |
| **UI-024** | `variables.css` держит примитивы **и кросс-тематические дефолты компонентов** (пагинация, скроллбары, GL-акценты, login). Это осознанный приём: тема, у которой нет своего значения, не оставляет токен unset. Значение, которое обязано меняться от темы к теме, определяется в файле темы. | [глаз] |
| **UI-025** | У поверхности ровно **две роли**, и роль решает, чем её красить. **Хром** (`.app-sidebar`, `.app-header`, `.app-panel`, `.page__header`) — лёгкая полупрозрачная заливка + `backdrop-filter: var(--glass-filter)`; текст поверх картинки добирает `text-shadow: var(--text-on-image-shadow)`. **Контент** (`--sheet-bg` на `.page__content`, `--card-bg`, таблицы) — плотная заливка **без** размытия. | [глаз] |
| **UI-026** | `backdrop-filter` на карточке запрещён: он создаёт containing block для `position: fixed` потомков, а внутри карточки живёт `.card-animated__nav-backdrop` с `fixed` — тот перестанет крыть экран. Читаемость контента даёт плотность заливки, а не размытие. | [глаз] |
| **UI-027** | Инвариант «ярлык == его лист»: активный ярлык и лист под ним обязаны композититься на один задник. Поэтому **если `--sheet-bg` полупрозрачен, `--tabs-bar-bg` обязан быть `transparent`** — иначе «ушко» ярлыка получит вторым слоем заливку бара, а лист нет, и фоны разойдутся. Разбор — в комментарии у `.page__tabs` в `layout.css`. | [глаз] |

Токены Thaw (`--colorNeutral*`, `--thaw-*`) приходят из библиотеки в рантайме —
это отдельная система, в нашем CSS они не определяются (генератор их отделяет).

## 4. Инлайн-стили

| ID | Правило | |
|----|---------|--|
| **UI-030** | `style=` / `attr:style=` — только для значений, вычисляемых в рантайме (ширина колонки, `padding-left` по глубине дерева, прогресс). Всё статическое — классом. | [скилл] |

> Сейчас в коде ~4 400 инлайн-стилей. Правило применяется **к новому и
> изменённому коду**; массовая зачистка — отдельная работа. Поэтому `/ui-check`
> и работает по диффу, а не по всему репозиторию.

## 5. Компоненты

| ID | Правило | |
|----|---------|--|
| **UI-040** | Колонки на detail-страницах — `div.detail-grid` / `div.detail-grid__col`, не `<Flex>` и не инлайн `display:grid`. | [скилл] |
| **UI-041** | Карточки — `<CardAnimated delay_ms=N>` (шахматный stagger 0/40/80/120), не Thaw `<Card>`. | [авто] |
| **UI-042** | Модалки — `ModalFrame` + `ModalStackService` (ADR-0004). Свои `modal-overlay`/`modal-content` дивы не заводить. | [авто] |
| **UI-043** | На одном экране — один набор кнопок: либо кастомный `.button`, либо Thaw `<Button>`. Не смешивать. | [глаз] |

## 6. Таблицы

Санкционированных способа **два**. Третьего нет.

1. **Thaw `<Table>`** — по умолчанию. Обёртка — одна `div.table-wrapper`.
2. **Сырой `<table class="table__data">`** — когда нужна липкая первая колонка
   или многоуровневая шапка, чего Thaw не даёт. Для матриц — `.data-matrix`.

| ID | Правило | |
|----|---------|--|
| **UI-050** | Один из двух способов выше. Новое семейство `.<что-то>-table` не заводить. | [скилл] |
| **UI-051** | Ровно одна обёртка `.table-wrapper`. Вложенность `.table-wrapper > .table-container` / `.list-container` — антипаттерн. | [авто] |
| **UI-052** | Шапка всегда по левому краю. `.table__header-cell--right` не применять. Числа выравниваются по значению: `.table__cell--right`. | [авто] |
| **UI-053** | Оформление таблицы страницы — **модификатор поверх** `.table__header-cell` / `.table__cell` / `.table__row`, а не собственный набор правил с теми же объявлениями. | [скилл] |

**Образец** — `.data-matrix` (`components.css`): общая база + модификаторы
страниц (`roles-matrix`, `skills-matrix`, GL-матрица). Единственное место, где
это с самого начала сделано правильно; новые таблицы копировать с него.

### `spec-list` — список именованных пунктов

Для интерфейсов до ~200 строк, где у пункта есть короткое имя, технический код,
длинное описание, несколько колонок-характеристик и категория (p903 «Поля»,
`sys_task_type_registry`). Даёт готовыми: тулбар с быстрым поиском, режим
«кратко/подробно» (`spec-list--compact` скрывает `spec-list__note`), подсветку
строки рамкой вместо смены фона и цветную полосу категории через рантайм-переменную
`--spec-cat`. Категорию **не** оформлять заливкой строки — она конфликтует с hover.
Бейджи брать из `.badge`, чипы-переключатели — из `dpc-mode-tab`.

> Thaw `<Table>` для таких списков не подходит: `.thaw-table-cell{height:36px!important}`
> ломает двухстрочную строку в подробном режиме, а `.thaw-table-row:hover{background:
> transparent!important}` стирает окраску строки. Здесь — сырой `table__data` плюс
> `table_utils::init_column_resize` (ширины переживают перезагрузку, Thaw так не умеет).

Разбор реактивных антипаттернов Leptos вокруг таблиц («RefCell already
borrowed», «Reactive value has already been disposed», условный рендер таблицы,
run-once init для resize/crosshair) — `table-standards.md`. Это **пояснительное
приложение**, а не второй стандарт.

### Общий компонент таблицы

`<StandardTable>` пока **нет**, и текущий набор мелких примитивов — не замена:
`SortableHeaderCell` имеет 1 применение против ~40 файлов, копипастящих ровно
ту разметку, которую он и умеет. Вывод зафиксирован: выигрыш возможен только на
уровне таблицы целиком, мелкая нарезка не приживается. Решение о компоненте —
отдельное, по результатам схлопывания CSS.

## Кто чем проверяет

| Инструмент | Что даёт | Охват |
|------------|----------|-------|
| `tools/gen_ui_registry.ps1` → `UI_REGISTRY.md` | факты и правила **[авто]** | всё приложение, детерминированно |
| Скилл `/ui-check` | правила **[скилл]**, суждение по разметке | только дифф |
| pre-commit hook | предупреждение о блоке вне allowlist | staged CSS |
| Страница **DOM Inspector** (вкладка `dom_inspector`) | реальный DOM: структура, id, категория | **только открытые вкладки** |

Про DOM Inspector важно понимать его потолок: он видит лишь то, что сейчас
открыто, поэтому «проверить приложение» им нельзя — для этого есть статический
чекер. Его роль — **отладка конкретной страницы в живом DOM** (посмотреть дерево,
убедиться, что `id` и категория проставились). Набор правил в нём намеренно узкий
и расширять его не нужно.
