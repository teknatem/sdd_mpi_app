# Метрики продаж

Справочник определений для навыка `sales-analytics` / персоны «Аналитик продаж».
Официальные числа берём из DataView, не переизобретаем в сыром SQL.

## Где данные

- **Выручка/продажи (курируемый, 2 периода)** — `dv001_revenue` (источник
  `p904_sales_data`). Метрики: `revenue, order_count, avg_check, cost, commission,
  expenses, profit, profit_d`.
- **Гибкий ad-hoc по продажам** — схема `ds03_p904_sales` (та же p904).
- **KPI по строкам заказов** — `dv003_mp_order_line_turnovers` (revenue_price, revenue,
  coinvest, acquiring, cost, commission, returns).
- **Реестр продаж MP** — схема `ds02_mp_sales_register` (p900).
- **Заказы**: YM — `a013_ym_order`, WB — `a015_wb_orders`.

## Определения

- **Выручка** (`revenue`) — сумма продаж за период; источник истины — dv001, не
  собирать вручную из заказов.
- **Средний чек** (`avg_check`) = выручка ÷ число заказов (`order_count`).
- **Себестоимость** (`cost`) — закупочная стоимость проданного (COGS).
- **Комиссия** (`commission`) — удержания маркетплейса.
- **Прибыль** (`profit`) = выручка − себестоимость − комиссия − расходы (`expenses`).
  `profit_d` — прибыль с учётом дополнительных вычетов (более консервативная).
- **Маржинальность, %** = прибыль ÷ выручка × 100.
- **Доля возвратов** — `returns` (dv003) относительно выручки/числа заказов.

## Правила

- Сравнение периодов — через встроенный 2-периодный режим dv001 (P1 vs P2), а не двумя
  отдельными запросами.
- Для «официальных» цифр (выручка/прибыль/себестоимость) — только dv001/dv003.
  Сырой SQL — только для нестандартных разрезов.
- Финансовая сверка выручки (fina/ybuh, GL) — это уже финансовый слой, см. знание
  general-ledger / a034; для неё — навык `finance-analytics`.
