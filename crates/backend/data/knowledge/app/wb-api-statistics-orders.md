# WB Statistics API — заказы

Исторический поток заказов. Самый капризный эндпоинт интеграции: жёсткий лимит в один запрос
в минуту и молчаливое поведение на границе глубины хранения, которое легко принять за поломку
импорта.

## Назначение и владелец

`fetch_orders` в импортном клиенте WB. Наполняет агрегат a015.

## Эндпоинты

**`GET https://statistics-api.wildberries.ru/api/v1/supplier/orders`**

Параметры: `dateFrom` — курсор в формате `ГГГГ-ММ-ДДT00:00:00`, `flag=0`.

`dateTo` серверной фильтрации **не даёт**: конец периода отсекается уже на нашей стороне.
Курсор двигается по максимальному `lastChangeDate` страницы плюс миллисекунда, то есть чтение
идёт по времени изменения строки, а не по дате заказа. Поэтому поздние изменения статуса сами
попадают в следующее окно.

## Лимиты и поведение

1 запрос/мин. При 429 код читает `X-Ratelimit-Retry` (по умолчанию 65 с). Если WB просит ждать
дольше 300 с, запуск не блокируется: он завершается маркером отложенности, и задача переносится
планировщиком. Отдельно разбираются редиректы 301/302 и ошибки соединения — для последних
формируется подсказка про DNS, прокси, файрвол, VPN и TLS.

Максимальный период за один запрос — 31 день; задача режет длинные интервалы на куски по 30
дней с перекрытием в 1 день.

## Глубина истории

**Не документирована и меняется.** Statistics API хранит заказы ограниченное время; фактическую
границу можно узнать только опытным путём — по самой ранней строке, которую WB согласился
отдать.

Код это делает: если после фильтрации по концу периода не осталось ни одной строки, а WB при
этом что-то вернул, формируется сообщение с фактической границей в МСК и предложением
запросить период начиная с неё.

## Цепочка потребителей

Эндпоинт → **a015** (заказы WB) →

- **p909** — обороты по строкам заказов;
- **p916** — воронка продаж, стадия заказа;
- **Главная книга**.

Проведение идемпотентно: повторная загрузка удаляет проводки по регистратору и пишет заново.
Поставочная связь (`income_id`) проставляется не здесь, а импортом поставок
(см. `app__wb-api-marketplace-supplies`).

## Расписание

`task002_wb_orders_stats_hourly`, cron `0 0 * * * *` (UTC) — ежечасно.

## ⚠️ Расхождения

**За границей глубины хранения API отдаёт не ошибку, а старые строки.**
- *Официально*: поведение при слишком раннем `dateFrom` не описано.
- *На практике*: WB игнорирует запрошенную дату и возвращает самые старые доступные строки.
  После отсечения по концу периода не остаётся ничего, и импорт «успешно» завершается нулём —
  на экране это неотличимо от зависшей загрузки.
- *В коде сейчас*: случай распознаётся и превращается в сообщение с фактической границей.
- Статус: **подтверждено**.

**`dateTo` не работает как серверный фильтр.**
- *Официально*: параметр присутствует в описании метода.
- *На практике*: выдача им не ограничивается.
- *В коде сейчас*: используется только как условие остановки на нашей стороне.
- Статус: **подтверждено**.

**Заказы здесь и заказы FBS — разные вещи.** Этот эндпоинт даёт историю с задержкой;
оперативная картина новых заказов идёт через marketplace-api
(см. `app__wb-api-marketplace-orders`). Складывать их как один источник нельзя.
