# WB Statistics API — детальный финансовый отчёт по периоду

> **Legacy, но активно используется.** Эта статья описывает существующие `p903` и
> `task006_wb_finance`, их проводки и сверки. Новый Finance API реализован отдельно в
> `app__wb-api-finance-reports-v1`; миграции между контурами нет.

Единственный источник, по которому можно говорить о деньгах WB. Всё, что касается удержаний,
логистики, вознаграждения площадки и фактической выплаты, приходит отсюда, а не из продаж.

## Назначение и владелец

`fetch_finance_report_by_period` в импортном клиенте WB. Наполняет проекцию p903 — у этого
источника нет агрегата a0XX, он ложится сразу в проекцию.

## Эндпоинты

**`GET https://statistics-api.wildberries.ru/api/v5/supplier/reportDetailByPeriod`**

Параметры: `dateFrom`, `dateTo`, `rrdid` (курсор, начинается с 0), `limit=100000`,
`period="daily"`.

Пагинация по `rrdid`: следующая страница запрашивается с идентификатором последней строки.
Импорт идёт **по одному дню за запрос** — так повторный запуск за тот же день шлёт тот же
запрос, и результат сопоставим.

## Лимиты и поведение

**1 запрос в минуту.** При 429 код спит 65 с и повторяет — здесь ожидание не отменяет запуск,
в отличие от заказов. Ответ 204 (нет содержимого) обрабатывается как пустой день, а не ошибка.

Практическое следствие: две недели данных — это минимум 15 минут работы задачи. Максимальный
период за один запрос — 31 день.

## Глубина истории

Финансовые данные **появляются с задержкой 3–5 дней** после продажи: строка за вчера сегодня
может отсутствовать или быть неполной. Поэтому задача перезабирает хвост — по умолчанию 3 дня
перекрытия. Без перекрытия картина за последние дни всегда занижена.

## Цепочка потребителей

Эндпоинт → **p903** (финансовый отчёт WB) → **Главная книга, слой `fina`** с оборотами
`customer_revenue`, `customer_return`, `mp_rebill_logistic_cost`, `mp_ppvz_reward` и их
номенклатурными вариантами → **p914** (зеркало финансовых оборотов).

После загрузки выполняется сверка дня. Целостность контролируют quality-checks
`p903_gl_integrity` и `gl_projection_integrity`.

При изменении правил маппинга или проводок нужен репост документов через u508 — иначе Главная
книга останется со старыми оборотами.

## Расписание

`task006_wb_finance`, cron `0 0 1 * * *` (UTC) = 04:00 МСК, ежедневно.

## ⚠️ Расхождения

**Расхождение с продажами — не ошибка, а разные модели счёта.**
- *Официально*: оба метода отдают суммы по продажам.
- *На практике*: `forPay` из продаж считается упрощённо, `ppvz_for_pay` отсюда — точно.
  Совпадения не будет никогда.
- *В коде сейчас*: операционная аналитика строится на p904, финансовая — на p903 и Главной
  книге; источники не смешиваются.
- Статус: **подтверждено**.

**Свежий период всегда неполон.** Данные догоняют 3–5 дней, поэтому отчёт за текущую неделю
занижен по построению. Сравнивать нужно закрытые периоды.
