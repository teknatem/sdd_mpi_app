# WB Advert API — статистика рекламы (fullstats)

Дневные расходы, показы и клики по рекламным кампаниям. Источник рекламной части воронки и
всех метрик окупаемости рекламы.

## Назначение и владелец

`fetch_advert_fullstats` в импортном клиенте WB. Наполняет агрегат a026 (день × кампания).

## Эндпоинты

**`GET https://advert-api.wildberries.ru/adv/v3/fullstats`**

Параметры: `ids` (идентификаторы кампаний через запятую, до 50 за запрос), `beginDate`,
`endDate`.

Число запросов за запуск = месяцы × пачки кампаний. Кампании, завершённые раньше начала
периода, из выборки исключаются.

## Лимиты и поведение

Между пачками пауза 21 с. При 429 запуск **останавливает все оставшиеся пачки** — продолжать
бессмысленно, лимит уже исчерпан; недостающие дни доберёт следующий запуск.

Проведение в Главную книгу устойчиво к временным сбоям: до 8 попыток с нарастающей паузой.

## Глубина истории

Рекламные данные **появляются с задержкой до суток**: статистика за вчера сегодня может быть
неполной. Ежедневный запуск поверх уже загруженных дней это компенсирует.

## Цепочка потребителей

Эндпоинт → **a026** (дневная реклама WB) →

- **p911** — реклама в разрезе товаров;
- **p913** — атрибуция рекламных кликов к заказу;
- **p916** — воронка, маркетинговая стадия;
- **Главная книга** — обороты `advert_clicks_order_accrual` (резерв под клики, приведшие к
  заказу) и `advert_clicks_no_order` (клики без заказа, прямой расход).

Резерв закрывается позже, при загрузке продаж: a012 пишет встречный оборот
`advert_clicks_order_expense` (см. `app__wb-api-statistics-sales`). Поэтому порядок репоста
через u508 имеет значение: реклама должна проводиться раньше продаж.

## Расписание

`task011_wb_advert`, cron `0 0 6 * * *` (UTC) = 09:00 МСК, ежедневно. Есть отдельный режим
дозагрузки истории за произвольный период.

## ⚠️ Расхождения

**Интервал жёстко ограничен 31 днём.**
- *Официально*: ограничение в описании метода не выделено.
- *На практике*: запрос длиннее 31 дня отвергается с `400 {"detail":"max date range 31 days"}`.
- *В коде сейчас*: период режется на **календарные месяцы** — не на произвольные окна по 31
  дню. Границы месяцев дают стабильный запрос при повторном запуске (WB отдаёт его из
  собственного кэша) и читаемый лог.
- Статус: **подтверждено**.

**Свежие сутки всегда неполны** — данные догоняют до 24 часов, поэтому вчерашний ДРР по
горячим следам занижен.
