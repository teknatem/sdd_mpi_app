# WB Calendar API — акции

Календарь акций кабинета: какие акции идут и планируются, на каких условиях, какие товары в
них участвуют. Забирается тремя последовательными методами — по отдельности они бесполезны.

## Назначение и владелец

`fetch_calendar_promotions`, `fetch_promotion_details`, `fetch_promotion_nomenclatures` в
импортном клиенте WB. Наполняют агрегат a020.

## Эндпоинты

**`GET https://dp-calendar-api.wildberries.ru/api/v1/calendar/promotions`** — список акций.
Параметры: `startDateTime`, `endDateTime` (RFC3339, импорт передаёт границы суток),
`allPromo=false`. В ответе два раздела — текущие и предстоящие акции, они объединяются.

**`GET .../calendar/promotions/details`** — условия акций. Параметр `promotionIDs`
повторяется для каждой акции, до 100 идентификаторов на запрос; импорт бьёт список на пачки.

**`GET .../calendar/promotions/nomenclatures`** — товары акции. Параметры: `promotionID`,
`inAction`, `limit=1000`, `offset`. Запрашиваются **оба** состояния `inAction` — и участвующие
товары, и доступные для добавления.

## Лимиты и поведение

Явных лимитов в коде не учтено, пауз между вызовами нет.

Оба уточняющих метода деградируют мягко: при ошибке детали возвращают пустой результат, а
обход номенклатур прерывается с сохранением уже собранного. Логика простая — потерять условия
акции лучше, чем потерять сам факт акции.

## Глубина истории

Отдаётся окно вокруг запрошенного периода: прошедшие акции из календаря со временем уходят.
История участия накапливается в a020.

## Цепочка потребителей

Три эндпоинта → **a020** (акция WB). Дальше по проекциям не идёт; используется для объяснения
провалов цены и выручки в разборе.

## Расписание

`task009_wb_promotions`, cron `0 0 5 * * *` (UTC) = 08:00 МСК, ежедневно.

## ⚠️ Расхождения

**Для автоматических акций состав товаров недоступен.**
- *Официально*: метод номенклатур описан как общий для акций.
- *На практике*: для акций типа `auto` он не работает.
- *В коде сейчас*: такие акции пропускаются целиком — товарный состав у них остаётся пустым.
- Статус: **подтверждено**.

**Пустые детали не означают, что условий нет.** Из-за мягкой деградации отсутствие условий в
a020 может означать как «WB не отдал», так и «акция без условий». Различить по данным нельзя —
нужен лог. Кандидат в доработку: помечать причину отсутствия.
