# WB Analytics API — история воронки по дням

Дневные значения воронки по товарам: показы, переходы в карточку, добавления в корзину,
заказы. Основной источник маркетинговой части p916 для Wildberries.

## Назначение и владелец

`fetch_sales_funnel_history` в импортном клиенте WB. Наполняет a036 (документ на кабинет и
дату, строка на товар).

## Эндпоинты

**`POST https://seller-analytics-api.wildberries.ru/api/analytics/v3/sales-funnel/products/history`**

Тело: `selectedPeriod`, список `nmIds`, `skipDeletedNm: false`, `aggregationLevel: "day"`.

Товары запрашиваются пачками по 20 идентификаторов; список активных товаров даёт поиск из
`app__wb-api-funnel-products`. Ответ приходит либо массивом, либо в обёртке — разбор терпит оба
варианта, а литеральный `"null"` трактуется как пустой результат.

Загрузка периода замещающая: данные за период удаляются и записываются заново. WB
пересчитывает воронку задним числом, поэтому дописывание давало бы задвоение.

## Лимиты и поведение

**3 запроса/мин**, пауза 21 с между пачками, таймаут 180 с. Лимит общий с остальными
аналитическими методами кабинета.

## Глубина истории

**Примерно последняя неделя.** Окно больше 7 дней вернёт не историю, а пустые дни — данных за
них просто нет в ответе, и отличить это от «в эти дни не было активности» по ответу нельзя.

Настройка задачи по умолчанию — 7 дней, максимум 30 (последнее имеет смысл только для разбора,
не для штатной загрузки). Более глубокая история берётся другим путём — через выгрузку отчёта,
см. `app__wb-api-funnel-detail-report`.

## Цепочка потребителей

Эндпоинт → **a036** (дневная воронка WB) → **p916** (обороты воронки продаж, маркетинговая
стадия) → дашборд воронки и `quality/funnel_repair`.

## Расписание

`task023_wb_sales_funnel_daily`, cron `0 30 3,15 * * *` (UTC) = 06:30 и 18:30 МСК, по
экземпляру на кабинет.

## ⚠️ Расхождения

**Окно в неделю нигде не объявлено числом.**
- *Официально*: ограничение периода в описании метода явно не задано.
- *На практике*: примерно 7 дней; дальше приходят пустые дни без признака ошибки.
- *В коде сейчас*: окно по умолчанию 7 дней, ограничение зафиксировано в описании задачи.
- Статус: **подтверждено**.

**Пустой день неотличим от дня без активности.** Ответ не различает «нет данных» и «нули».
Кандидат в доработку: помечать дни за пределами окна как N/A, а не как нули — иначе воронка
выглядит правдоподобно и при этом неверно.
