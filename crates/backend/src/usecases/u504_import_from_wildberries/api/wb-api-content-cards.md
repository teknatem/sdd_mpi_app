# WB Content API — карточки товаров

Товарный справочник кабинета. От него зависит вся остальная цепочка: без карточки `nmID` из
продаж, заказов и рекламы не с чем связать — не будет ни номенклатуры, ни бренда, ни предмета.

## Назначение и владелец

`fetch_product_list` в импортном клиенте WB. Заполняет агрегат a007 и связку
`nmID ↔ карточка/бренд/предмет/баркод`.

## Эндпоинты

**`POST https://content-api.wildberries.ru/content/v2/get/cards/list`**

Тело запроса:

```
{ "settings": { "cursor": { "updatedAt": ..., "nmID": ..., "limit": N },
                "filter":  { "withPhoto": -1 } },
  "limit": N }
```

Пагинация курсорная: следующая страница запрашивается с `updatedAt` и `nmID` последней
строки предыдущей. Фильтр `findByNmID` не используется — забирается весь каталог.

## Лимиты и поведение

300 запросов/мин. Пауз между страницами нет, ретраев нет. Ошибки соединения различаются по
типу (таймаут / отказ соединения / ошибка запроса) и попадают в лог отдельными сообщениями.

Есть отладочный режим, который дёргает десяток вариаций запроса (другой лимит, пустой фильтр,
корзина, список предметов, продолжение пагинации) — он остался с разбора инцидента, когда WB
отдавал 6–10 карточек вместо примерно тысячи.

## Глубина истории

Неприменимо: эндпоинт отдаёт текущее состояние каталога, истории карточек у него нет.

## Цепочка потребителей

Эндпоинт → **a007** (товар маркетплейса) → связывание `nmID` с номенклатурой для a012, a015,
a026, a036, a037 и всех проекций, где есть `marketplace_product_ref`. Отдельной проекции у
a007 нет — он справочник, а не факт.

Quality-check `marketplace_product_ref_required` ловит строки проекций, для которых карточка
так и не нашлась.

## Расписание

`task003_wb_products`, cron `0 0 3 * * *` (UTC) = 06:00 МСК, ежедневно.

## ⚠️ Расхождения

**`withPhoto` обязателен, хотя выглядит необязательным.**
- *Официально*: фильтр описан как опциональный отбор по наличию фотографии.
- *На практике*: без явного `withPhoto: -1` WB режет выдачу — возвращается небольшая часть
  каталога, и это не выглядит ошибкой.
- *В коде сейчас*: `-1` («все карточки») передаётся всегда, в коде есть комментарий.
- Статус: **подтверждено**.

**`limit` живёт внутри курсора.**
- *Официально*: описан как параметр настроек.
- *На практике*: WB читает его из `settings.cursor.limit`.
- *В коде сейчас*: передаётся и там, и на верхнем уровне.
- Статус: **подтверждено**.

**`cursor.total` — не размер каталога.**
- *Официально*: поле выглядит как «всего карточек».
- *На практике*: возвращает количество строк в текущей странице, поэтому как признак конца
  выборки бесполезно.
- *В коде сейчас*: обход останавливается по пустой или неполной странице, `total` не
  используется как ожидаемое число.
- Статус: **подтверждено**.
