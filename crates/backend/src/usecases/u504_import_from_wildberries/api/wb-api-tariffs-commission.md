# WB Common API — тарифы комиссий

Ставки комиссий по предметам и категориям. Нужны, чтобы считать ожидаемую комиссию до того,
как придёт финансовый отчёт.

## Назначение и владелец

`fetch_commission_tariffs` в импортном клиенте WB. Наполняет проекцию p905.

## Эндпоинты

**`GET https://common-api.wildberries.ru/api/v1/tariffs/commission?locale=ru`**

Единственный параметр — `locale`, он влияет на язык названий категорий в ответе. Пагинации
нет, период не задаётся: один запрос отдаёт весь справочник.

## Лимиты и поведение

Ограничений по частоте не замечено, ретраев нет.

## Глубина истории

**Истории нет.** Эндпоинт возвращает срез на момент запроса — узнать, какая ставка
действовала месяц назад, через API невозможно.

Историю ведёт проекция p905: каждая загрузка добавляет срез с датой, и накопленная история —
наша, а не WB. Пропущенная загрузка невосстановима: задним числом ставку взять неоткуда.

## Цепочка потребителей

Эндпоинт → **p905** (история комиссий WB). Дальше по цепочке проекций не идёт — используется
как справочник при расчётах.

## Расписание

`task007_wb_commissions`, cron `0 0 2 * * 1` (UTC) = понедельник 05:00 МСК, еженедельно.

## ⚠️ Расхождения

**Ставка из справочника и удержание в отчёте — разные числа.**
- *Официально*: справочник даёт комиссию по категории.
- *На практике*: фактическое вознаграждение площадки в финансовом отчёте зависит ещё от
  модели работы, акций и логистики. Справочник — ожидание, отчёт — факт.
- *В коде сейчас*: p905 не участвует в проводках Главной книги; деньги берутся из p903.
- Статус: **подтверждено**.

**Еженедельного среза может не хватить.** Если WB меняет ставку внутри недели, момент
изменения будет потерян — в истории останется только ставка на понедельник. Кандидат в
доработку, если понадобится точная датировка изменений.
