# WB Analytics API — поисковая аналитика и запросы

Видимость товаров в поисковой выдаче и запросы, по которым их находят. Самый молодой и самый
непроверенный кусок интеграции: разбор ответа написан терпимо и ждёт сверки на живых данных.

## Назначение и владелец

`fetch_search_report` и `fetch_search_texts` в импортном клиенте WB. Наполняют агрегат a040.

## Эндпоинты

**`POST https://seller-analytics-api.wildberries.ru/api/v2/search-report/table/details`** —
строки по товарам. Тело: текущий период, **прошлый период**, сортировка по `openCard`,
`positionCluster: "all"`, флаги включения заменённых товаров и поисковых текстов, `limit=1000`.

`pastPeriod` обязателен: WB считает метод сравнительным. Прошлый период вычисляется как окно
той же длины, заканчивающееся за день до текущего.

**`POST .../api/v2/search-report/product/search-texts`** — топ поисковых запросов по товарам.
Тело: те же периоды, список товаров, сортировка по средней позиции, лимит (импорт берёт 30).

Запросы забираются **не по всему каталогу**: только для товаров с реальной поисковой
активностью и не более чем для 50 из них. Причина прозаичная — при паузе 21 с между вызовами
полный обход каталога занимал минуты на кабинет.

## Лимиты и поведение

3 запроса/мин, пауза 21 с, таймаут 180 с.

Отказ по подписке обрабатывается мягко: 403 превращается в предупреждение, запуск завершается
успешно и без данных. Кабинет без «Джема» не должен ронять весь импорт.

Для запросов деградация ещё мягче: при любой ошибке документ сохраняется без поисковых
текстов.

## Глубина истории

Задаётся периодом; штатное окно задачи — 1 день. Замещающая загрузка за период.

## Цепочка потребителей

Эндпоинты → **a040** (поисковая аналитика WB). Дальше **никуда** — это конечная точка.

## Расписание

`task024_wb_search_analytics_daily`, cron `0 0 4,16 * * *` (UTC) = 07:00 и 19:00 МСК, по
экземпляру на кабинет.

## ⚠️ Расхождения

**Показов нет — есть видимость в процентах.**
- *Официально*: метод относится к поисковой аналитике.
- *На практике*: отдаёт долю видимости, а не счётчик показов.
- *В коде сейчас*: a040 **намеренно не входит в воронку p916** — подставить видимость вместо
  показов значило бы получить правдоподобную, но ложную воронку. Показы WB остаются N/A.
- Статус: **подтверждено**.

**Имена полей ответа не верифицированы.**
- *Официально*: структура описана в документации.
- *На практике*: живой сверки не было; известно, что ответ по запросам приходит плоским
  списком (одна запись на поисковый текст), а не вложенным в товары, как можно было ожидать.
- *В коде сейчас*: разбор терпит обе формы, сырой ответ пишется в лог отдельной меткой — при
  первом живом прогоне имена полей нужно сверить.
- Статус: **требует проверки**.

**Сравнение с прошлым периодом навязано методом.** Отдельно «просто за период» получить
нельзя; прошлый период всегда считается автоматически и на содержимое ответа влияет.
