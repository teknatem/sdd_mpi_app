# WB Analytics API — воронка по товарам и снимок остатков

Один эндпоинт используется двумя задачами в двух разных ролях: как поиск товаров с активностью
(чтобы знать, по каким `nmID` вообще спрашивать историю) и как полный снимок состояния
товаров — остатки, суммы, рейтинги.

## Назначение и владелец

`fetch_sales_funnel_products` (поиск) и `fetch_sales_funnel_products_full` (полный снимок) в
импортном клиенте WB. Наполняют a036 и a037.

## Эндпоинты

**`POST https://seller-analytics-api.wildberries.ru/api/analytics/v3/sales-funnel/products`**

Тело: `selectedPeriod` (начало и конец), сортировка по `openCard` по убыванию,
`skipDeletedNm: false`, `limit` (до 1000), `offset`.

Разбор ответа намеренно терпимый: полезная нагрузка ищется по нескольким возможным путям, а
идентификатор товара — по нескольким вариантам написания. WB меняет форму ответа между
версиями, и жёсткий разбор ломался бы молча.

## Лимиты и поведение

**3 запроса/мин на метод**, общие на кабинет. Между вызовами пауза 21 с.

Таймаут переопределён на 180 с: сравнение периодов по всему каталогу WB считает дольше, чем
общий шестидесятисекундный дефолт. При сетевых сбоях до 3 попыток; **429 не ретраится** —
ждать в цикле, когда лимит уже выбран, бессмысленно.

## Глубина истории

**Снимок только вперёд.** WB не отдаёт состояние остатков и рейтингов задним числом:
пропущенный запуск невосстановим, дырка в истории останется навсегда. Отсюда два запуска в
сутки — цена пропуска слишком высока.

## Цепочка потребителей

Поиск → список активных `nmID` → вход для `app__wb-api-funnel-history`, далее **a036** → p916.

Полный снимок → **a037** (снимок товара WB): остатки WB и продавца, суммы, рейтинг карточки и
рейтинг покупателей. Проекций у a037 нет — это конечная точка.

## Расписание

- `task020_wb_product_snapshot` (полный снимок), cron `0 0 3,15 * * *` (UTC) = 06:00 и 18:00 МСК;
- `task023_wb_sales_funnel_daily` (поиск), cron `0 30 3,15 * * *` (UTC) = 06:30 и 18:30 МСК.

Задачи заведены по экземпляру на кабинет и разведены на полчаса. Это не косметика: лимит
3 запроса/мин общий на кабинет, и одновременный старт гарантированно даёт 429 у обеих.

## ⚠️ Расхождения

**Ретроспективы нет.**
- *Официально*: метод описан как аналитика за выбранный период.
- *На практике*: остатки и рейтинги возвращаются на момент запроса, а не на дату периода.
  Восстановить вчерашний остаток нельзя.
- *В коде сейчас*: снимок пишется только вперёд, пропуск фиксируется как пропуск.
- Статус: **подтверждено**.

**Форма ответа нестабильна.**
- *Официально*: структура ответа зафиксирована.
- *На практике*: встречались разные обёртки полезной нагрузки и разные написания
  идентификатора товара; приходил и литеральный `"null"` вместо тела.
- *В коде сейчас*: разбор перебирает варианты и не падает.
- Статус: **подтверждено**.
