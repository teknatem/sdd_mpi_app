# YM API — механика асинхронных отчётов

Три отчёта Яндекс Маркета — по платежам, о реализации и аналитика показов — не отдают данные
в ответе. Они возвращают идентификатор задания, и дальше работает общий цикл: опросить статус,
получить подписанную ссылку, скачать файл. Механика одна на всех, различия — в формате и
кодировке файла.

## Назначение и владелец

`poll_report_status` (опрос) и три функции скачивания в импортном клиенте YM.

## Эндпоинты

**`GET /v2/reports/info/{reportId}`** — статус задания. Возвращает состояние и ссылку на файл.
Состояния: в очереди, обрабатывается, готово, ошибка.

**`GET <подписанная ссылка>`** — скачивание. Заголовок авторизации **не передаётся**: ссылка
уже подписана.

Три варианта обработки скачанного:

- текст — для аналитики показов;
- архив, из которого берётся первый CSV — для отчёта по платежам;
- архив, из которого берутся **все** CSV — для отчёта о реализации, там их несколько.

Каждый скачанный файл сохраняется на диск в подкаталог своего отчёта.

## Лимиты и поведение

Генерация проходит через общий для процесса последовательный лимитер с ключом
`business_id + endpoint`, поэтому кампании одного бизнеса и параллельные задачи делят одну
квоту. Без заголовков выдерживается 120 с для `goods-realization` и `united-netting`, 600 с
для `shows-sales`. После ответа расписание адаптируется по
`X-RateLimit-Resource-Remaining`, `X-RateLimit-Resource-Until` и `Retry-After`; статусы 420 и
429 считаются rate-limit и повторяются ограниченное число раз.

Политика опроса одинакова у всех трёх потребителей: **до 60 попыток с интервалом 5 секунд**,
то есть максимум 5 минут ожидания на отчёт. Первая пауза делается до первого опроса — сразу
после заказа отчёт заведомо не готов.

Опрос устойчив к сетевым сбоям: разрывы считаются и не прерывают ожидание. Прерывают только
явная ошибка формирования и исчерпание попыток.

Опрос выполняется от имени исходного подключения, даже если заказ отчёта делался в контексте
конкретной кампании: идентификаторы заданий принадлежат бизнесу.

## Глубина истории

Неприменимо — механика доставки, а не данных.

## ⚠️ Расхождения

**Формат файла не определяется по ссылке.**
- *Официально*: формат задаётся при заказе отчёта.
- *На практике*: Маркет отдаёт запрошенный JSON то напрямую, то упакованным в архив — это
  зависит от размера, а расширение в ссылке не меняется.
- *В коде сейчас*: тип определяется по сигнатуре архива в начале файла, а не по ссылке.
- Статус: **подтверждено**.

**Кодировки у отчётов разные.**
- *На практике*: отчёт по платежам приходит в UTF-8, отчёт о реализации — в CP1251.
- *В коде сейчас*: снимается метка порядка байтов, проверяется корректность UTF-8, и при
  неудаче содержимое декодируется как CP1251.
- Статус: **подтверждено**.

**Пять минут ожидания — жёсткий потолок.** Для большого периода отчёт может готовиться дольше,
и запуск завершится по исчерпанию попыток, хотя Маркет отчёт всё же сформирует. Кандидат в
доработку: сохранять идентификатор задания и забирать файл при следующем запуске, а не
заказывать отчёт заново.
