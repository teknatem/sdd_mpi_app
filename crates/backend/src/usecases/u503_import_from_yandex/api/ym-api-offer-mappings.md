# YM API — товарный каталог бизнеса

Товарный справочник уровня бизнеса. Даёт связку внутреннего артикула с товаром Маркета и
баркодами — без неё заказы и аналитику не с чем сопоставить.

## Назначение и владелец

`fetch_product_list` в импортном клиенте YM. Наполняет агрегат a007 и проекцию баркодов p901.

## Эндпоинты

**`POST /v2/businesses/{businessId}/offer-mappings`**

Пагинация: `limit` (импорт берёт 100) и официальный `pageToken` передаются **в параметрах запроса**, тело
остаётся пустым. Обход идёт по токену следующей страницы до его исчезновения; дополнительно
стоит защита от зацикливания — если токен не изменился, обход прекращается.

Общее число товаров берётся из ответа один раз и используется как ожидаемый итог.

## Лимиты и поведение

Ретраев и пауз нет. Ошибки соединения разбираются по типу и переводятся в понятный текст.

## Глубина истории

Неприменимо — текущее состояние каталога.

## Цепочка потребителей

Эндпоинт → **a007** (товар маркетплейса) и **p901** (баркоды номенклатуры) → связывание
товаров во всех остальных импортах YM.

## Расписание

Отдельной задачи нет: входит в общий импорт YM и запускается вручную из интерфейса импорта.

## ⚠️ Расхождения

**Пагинация не работает через тело запроса.**
- *Официально*: метод описан как POST с параметрами в теле.
- *На практике*: тело для пагинации игнорируется — `limit` и токен страницы нужно передавать
  в параметрах запроса.
- *В коде сейчас*: пагинация вынесена в параметры, в коде есть поясняющий комментарий.
- Статус: **подтверждено**.

**Категория приходит не из маппинга.**
- *Официально*: сопоставление товара содержит сведения о категории.
- *На практике*: в маппинге категории нет — она берётся из самого предложения, а
  идентификатор категории остаётся незаполненным.
- *В коде сейчас*: сохраняется только название категории.
- Статус: **подтверждено**. Кандидат в доработку, если понадобится разрез по категориям YM.

**Имя токена чувствительно к регистру.** Официальное имя — `pageToken`; `page_token` в URL
не используется. Внутреннее Rust-поле остаётся `page_token`, но сериализуется и выводится в
диагностике как `pageToken`.
