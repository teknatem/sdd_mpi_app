# YM API — отчёт о реализации

Официальный отчёт о реализации — то, что Маркет считает проданным с точки зрения документов.
Формирует слой учёта `ybuh` и существует ради сверки с фактическими расчётами из отчёта по
платежам.

## Назначение и владелец

`generate_realization_report` в импортном клиенте YM. Наполняет агрегат a034.

## Эндпоинты

**`POST /v2/reports/goods-realization/generate?format=CSV`**

Тело: `campaignId`, `year`, `month`. Отчёт **помесячный и по кампании** — произвольный период
задать нельзя, идентификатор бизнеса не принимается.

Дальше — общая механика асинхронных отчётов (см. `app__ym-api-reports-machinery`).

В архиве несколько файлов. Используются два: переданное покупателю (выручка) и возвращённое
(со знаком минус). Файлы про передачу в доставку, невыкуп и потери **не читаются намеренно** —
это не реализация. Даты строк подрезаются по границам месяца отчёта.

## Лимиты и поведение

Официальный лимит без подписки — **1 запрос в 2 минуты** (с «Медиумом» — 1 запрос в минуту).
Он разделяется на уровне бизнеса, хотя тело запроса содержит кампанию. Общий процессный
лимитер использует ключ `business_id + goods-realization`, безопасный интервал 120 с и
адаптацию по rate-limit headers; 420/429 повторяются ограниченно.

Каждая пара «кампания + месяц» изолирована: сбой сети, лимит, отказ формирования или модель
размещения без такого отчёта (например DBS) логируются и пропускаются, не роняя весь импорт.

## Глубина истории

Помесячно; ограничения глубины в коде не зафиксировано.

## Цепочка потребителей

Эндпоинт → **a034** (реализация YM) →

- **Главная книга, слой `ybuh`** — обороты выручки и её сторнирования;
- **p915** — события заказа.

Зеркало финансовых оборотов p914 для этого слоя **не строится**: `ybuh` — это не `fina`, и
смешивать их в одной проекции нельзя.

В карточке документа есть сверка реализации с заказами a013 по дате доставки и сверка
возвратов с a016. Заказы, найденные в отчёте, но отсутствующие в a013, можно дозагрузить —
это второй потребитель карточки заказа (см. `app__ym-api-orders`).

## Расписание

**Запланированной задачи нет.** Отчёт загружается только вручную из интерфейса импорта YM.

## ⚠️ Расхождения

**Лимит считается на бизнес, а не на кампанию.**
- *Официально*: ограничение описано как «один запрос в минуту».
- *На практике*: счётчик общий на бизнес, поэтому обход десяти кампаний за месяц — это десять
  попаданий в лимит подряд, а не десять независимых запросов.
- *В коде сейчас*: пять попыток с паузой 65 с на каждую пару «кампания + месяц».
- Статус: **подтверждено**.

**Ограничение отдаётся нестандартным кодом.**
- *На практике*: используется статус 420, а не только 429.
- *В коде сейчас*: обрабатываются оба, плюс распознавание по тексту ответа.
- Статус: **подтверждено**.

**Не все модели размещения дают отчёт.** Для части кампаний (например DBS) отчёт не
формируется вовсе; это ожидаемо и обрабатывается как пропуск.

**Отсутствие задачи в расписании — риск.** Слой `ybuh` наполняется только руками, то есть
сверка выручки выполняется тогда, когда о ней вспомнили. Кандидат в доработку.
