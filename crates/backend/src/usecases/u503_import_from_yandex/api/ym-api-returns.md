# YM API — возвраты

Возвраты и невыкупы по заказам Яндекс Маркета. Тонкость не в самом методе, а в том, что из
него берётся: часть событий сюда дублируется из заказов, и проводить их дважды нельзя.

## Назначение и владелец

`fetch_returns` в импортном клиенте YM. Наполняет агрегат a016.

## Эндпоинты

**`GET /v2/campaigns/{campaignId}/returns`**

Параметры: `fromDate` и `toDate` в формате `ГГГГ-ММ-ДД`, `limit=100` (максимум), `pageToken`.

Написание параметров здесь отличается от каталога товаров: размер страницы называется `limit`,
а не `pageSize`, токен — `pageToken`, а не `page_token`. Это различие на стороне Маркета, а не
небрежность в коде.

Ответ приходит в обёртке со статусом и результатом — не так, как у заказов, где список лежит
на верхнем уровне.

## Лимиты и поведение

Ограничителя частоты нет. Обход по токену страницы, с защитой в 100 страниц.

## Глубина истории

Период фильтрует **дату обновления возврата, а не создания**. Практическое следствие приятное:
поздние изменения статуса сами попадают в окно загрузки, и перезабирать глубокую историю ради
них не нужно. Задача берёт окно с перекрытием в 2 дня и режет период кусками по 14 дней.

## Цепочка потребителей

Эндпоинт → **a016** (возвраты YM) →

- **p904** — витрина продаж;
- **p916** — воронка, **только возвраты**.

Дата когорты возврата берётся не из самого возврата, а из исходного заказа в a013. Отсюда
жёсткое требование к порядку репоста через u508: **a013 должен проводиться раньше a016**,
иначе когорту не к чему привязать.

## Расписание

`task018_ym_returns`, cron `0 0 7 * * *` (UTC) = 10:00 МСК, ежедневно.

## ⚠️ Расхождения

**Невыкупы в воронку не проводятся — намеренно.**
- *Официально*: метод отдаёт и возвраты, и невыкупы.
- *На практике*: невыкуп — то же физическое событие, что отказ в заказе (он приходит и из
  a013). Проведение обоих задвоило бы отказы в воронке.
- *В коде сейчас*: в p916 попадают только собственно возвраты, невыкупы отфильтровываются.
- Статус: **подтверждено**.

**Отбор по дате обновления легко принять за отбор по дате возврата.** Возврат, созданный
месяц назад и обновлённый вчера, попадёт во вчерашнее окно. Для загрузки это правильно, но
для отчёта «возвраты за период» этот же признак даст неверный ответ, если брать его напрямую.
