# YM API — магазины, бизнес и проверка подключения

Точка входа во всю интеграцию с Яндекс Маркетом. Подключение в системе описывает **бизнес**,
а данные лежат по **магазинам** — и разложить одно на другое можно только через этот метод.

## Назначение и владелец

`fetch_campaigns` в импортном клиенте (обход магазинов бизнеса) и `seller_info` /
`test_connection` в клиенте маркетплейса (проверка подключения).

## Эндпоинты

**`GET /campaigns`** — список магазинов. Параметры: `page`, `pageSize=50`. Обход постраничный
с защитой от зацикливания — не более 100 страниц.

Из ответа берутся: идентификатор кампании, домен, **`placementType`** (FBS, FBY, DBS, LAAS),
доступность API и принадлежность бизнесу. Импорт отбирает те кампании, чей бизнес совпадает с
подключением, и обходит их все — заказы, возвраты, реализацию и аналитику.

Если бизнес не задан или список не получен, используется единственная кампания из настроек
подключения. Это запасной путь, а не штатный режим.

**`GET /v2/campaigns?limit=100`** — та же выборка для карточки подключения.

**`POST /v2/auth/token`** — сведения о токене. Вызывается **только** для ключей типа Api-Key:
для OAuth метод недоступен. Ошибка не роняет проверку подключения, а попадает в её результат.

## Лимиты и поведение

Специальных ограничений нет. Клиент проверки подключения работает с укороченными таймаутами
(10–15 с).

## Глубина истории

Неприменимо — справочник текущего состояния.

## Цепочка потребителей

Метод не пишет данные напрямую, но задаёт измерение: `placementType` сохраняется в заголовке
заказа a013 как модель размещения (`fulfillment_type`) и **заменяет магазин** в аналитике YM.

Практическое следствие: все задачи YM обходят магазины бизнеса целиком, а разрез по магазину в
отчётности не заводится — вместо него используется модель размещения.

## Расписание

Отдельной задачи нет: вызывается в начале каждого импорта YM и по кнопке проверки подключения.

## ⚠️ Расхождения

**Версия в комментарии кода устарела.**
- *Официально*: актуальна вторая версия методов.
- *В коде сейчас*: проверка подключения ходит на неверсионированный путь `/campaigns`, хотя
  комментарий рядом утверждает, что используется v2.1.
- Статус: **подтверждено**. Кандидат в доработку — привести комментарий и путь к одному виду.

**Один ключ на бизнес, но кампании могут различаться по доступности.** Ответ содержит признак
доступности API по кампании; сейчас он читается для карточки подключения, но на обход
кампаний не влияет — недоступная кампания просто даст ошибки в своих импортах.
