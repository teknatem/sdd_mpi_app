# YM API — обзор, карта эндпоинтов и расхождения

В отличие от Wildberries, у Яндекс Маркета всё живёт на одном хосте
`https://api.partner.market.yandex.ru`. Зато здесь своя сложность — **двухуровневая модель**:
данные принадлежат либо бизнесу целиком, либо отдельной кампании (магазину), и выбор уровня
меняет смысл цифр.

## Общие правила

**Авторизация.** Заголовок `Api-Key: <токен>` либо `Authorization: Bearer <токен>` для OAuth.
Базовая авторизация не поддерживается и отклоняется до отправки запроса.

**Два уровня данных.** Часть методов принимает `businessId` (весь бизнес, все модели
размещения сразу), часть — `campaignId` (конкретный магазин). Это не деталь адресации, а
измерение: сверка выручки между слоями учёта опирается именно на разницу
«бизнес-уровень против уровня кампании» (см. `app__ym-api-united-netting` и
`app__ym-api-goods-realization`).

**Транспорт.** Общий клиент: таймаут 60 с, браузерный `User-Agent`, отключённый системный
прокси. Все запросы и ответы пишутся в `yandex_api_requests.log` с ротацией по 10 МБ и
обрезкой длинных тел.

**Отчёты асинхронные.** Три из восьми рабочих методов не отдают данные напрямую, а заказывают
файл: заказ → опрос статуса → скачивание по подписанной ссылке. Общая механика вынесена в
`app__ym-api-reports-machinery`.

## Карта эндпоинтов

| Метод | Уровень | Статья | Куда попадает |
|---|---|---|---|
| `GET /campaigns`, `GET /v2/campaigns` | бизнес | `app__ym-api-campaigns` | — (справочник магазинов) |
| `POST /v2/auth/token` | — | `app__ym-api-campaigns` | — (проверка ключа) |
| `POST /v2/businesses/{id}/offer-mappings` | бизнес | `app__ym-api-offer-mappings` | a007, p901 |
| `GET /campaigns/{id}/orders` | кампания | `app__ym-api-orders` | a013 |
| `GET /campaigns/{id}/orders/{orderId}` | кампания | `app__ym-api-orders` | a013 |
| `GET /v2/campaigns/{id}/returns` | кампания | `app__ym-api-returns` | a016 |
| `POST /v2/reports/united-netting/generate` | **бизнес** | `app__ym-api-united-netting` | p907 |
| `POST /v2/reports/goods-realization/generate` | **кампания** | `app__ym-api-goods-realization` | a034 |
| `POST /v2/reports/shows-sales/generate` | кампания | `app__ym-api-shows-sales` | a041 |
| `GET /v2/reports/info/{reportId}` | — | `app__ym-api-reports-machinery` | — |

## Модель лимитов

| Лимит | Где | Как обходим |
|---|---|---|
| 1 запрос/2 мин | `goods-realization`, `united-netting` | общий лимитер `business_id + endpoint`, headers, 420/429 |
| 1 запрос/10 мин | `shows-sales` | общий лимитер, безопасный интервал 600 с, headers, 420/429 |
| ограничение по тарифу | одновременная генерация отчётов (без подписки — 1) | последовательный запуск |
| окно фильтра 30 дней | список заказов | нарезка периода на подокна |
| ~600 запросов/мин на кабинет | остальное | **клиентского ограничителя нет** |

Общий лимит в документации объявлен, но в коде дросселя под него не заведено — квоты
различаются по методам, и полагаться на одно число нельзя.

Отдельно стоит отметить рейт-лимит с кодом **420**: Яндекс использует нестандартный статус,
и обработка ограничений завязана на него, а не только на 429.

## Расписание

Cron в задачах записан в **UTC**, МСК = UTC+3.

| Задача | Cron (UTC) | МСК | Эндпоинты |
|---|---|---|---|
| task013 заказы | `0 */5 * * * *` | каждые 5 мин | orders, orders/{id} |
| task019 отчёт по платежам | `0 0 2 * * *` | 05:00 | united-netting |
| task018 возвраты | `0 0 7 * * *` | 10:00 | returns |
| task026 аналитика | не засеяна | — | shows-sales |
| — | нет задачи | — | goods-realization (только вручную) |

## Сводка расхождений — вход для доработок

| Что | Расхождение | Статус |
|---|---|---|
| `orders` | поля `items[].status` не существует; судьба позиции лежит в `items[].details` | подтверждено |
| `united-netting` | нет фильтра по дате изменения — правки задним числом ловятся только перезабором | подтверждено |
| `goods-realization` | лимит 1 запрос/мин на **бизнес**, а не на кампанию; при обходе кампаний бьётся почти всегда | подтверждено |
| `shows-sales` | глубина 90 дней без подписки, 400 на «Медиуме»; пропущенное невосстановимо | подтверждено |
| `shows-sales` | нулевые метрики опускаются — отсутствие поля значит N/A, а не ноль | подтверждено |
| отчёты | приходят то JSON, то ZIP; кодировки разные (UTF-8 и CP1251) | подтверждено |
| `returns` | фильтр по дате **обновления**, а не создания | подтверждено |
| `orders/{orderId}` | вызывается по разу на заказ без ограничителя частоты | подтверждено |
| `goods-realization` | нет запланированной задачи — загрузка только руками | подтверждено |
