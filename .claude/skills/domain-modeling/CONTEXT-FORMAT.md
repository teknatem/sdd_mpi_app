# CONTEXT.md Format

> Адаптировано под этот проект: один контекст, русский язык, глоссарий частично уже
> существует. Апстрим-вариант с `CONTEXT-MAP.md` и мульти-контекстами здесь не применяется.

Репозиторий — **один контекст**. Глоссарий один: `CONTEXT.md` в корне.
`CONTEXT-MAP.md` не заводить.

## Структура

```md
# {Название контекста}

{Одно-два предложения: что это за контекст и зачем он существует.}

## Язык

**Заказ**:
{Одно-два предложения, описывающих термин}
_Не говорить_: покупка, транзакция

**Реализация**:
Официальный отчёт маркетплейса о проданном товаре, основа бухгалтерского слоя.
_Не говорить_: продажа, отчёт о продажах
```

## Правила

- **Быть категоричным.** Если у понятия несколько названий — выбрать одно лучшее,
  остальные перечислить в `_Не говорить_`.
- **Определения короткие.** Одно-два предложения. Описывать, что термин *есть*,
  а не что он делает.
- **Только термины, специфичные для этого проекта.** Общие программистские понятия
  (таймауты, типы ошибок, паттерны утилит) не входят, даже если активно используются.
  Перед добавлением спроси: это понятие уникально для домена или общее для программирования?
- **Код-идентификатор ≠ термин UI.** В этом проекте они расходятся намеренно
  (`dsXX` → «Схемы таблиц», `semantic_layer` → «Источники данных»). Если у понятия
  есть отдельная подпись в интерфейсе, укажи и её — расхождение само по себе факт домена.
- **Двуязычность.** Термины домена — по-русски (язык предметной области: маркетплейсы, учёт,
  1С). Код-идентификаторы (`a015`, `p904`, `fina`) приводить как есть, не переводить.
- **Группировать по подзаголовкам**, когда складываются естественные кластеры
  (учёт / маркетплейсы / слой данных). Плоский список тоже нормально, если терминов мало.

## Чего в CONTEXT.md быть не должно

Только глоссарий. Не спека, не черновик, не место для решений по реализации:

- решения → `memory-bank/decisions/` (ADR);
- структура кода, схема именования `a0XX`/`p9XX`, карта роутов → `CLAUDE.md` и `ARCHITECTURE.md`;
- бизнес-правила и текущие планы → авто-память Claude Code.

`CONTEXT.md` отвечает на «что это слово значит», а не «как это работает».

## Что уже есть

Часть словаря уже зафиксирована в других файлах — **сначала прочитай их**, чтобы не
переспрашивать то, что решено, и не противоречить:

- `CLAUDE.md` — таблица схемы именования (`a0XX`, `p9XX`, `dsXX`, `dvXX`, `d4XX`, `u5XX`,
  `task0XX`), три роли источников данных, соответствие «код ↔ UI»;
- `ARCHITECTURE.md` — каталог всех объектов с описаниями (генерируется из кода);
- авто-память Claude Code — бизнес-факты по WB/YM/ГК, различия слоёв `fact`/`fina`/`ybuh`.

При расхождении между `CONTEXT.md` и кодом прав код — сначала проверь код, потом поправь глоссарий.
